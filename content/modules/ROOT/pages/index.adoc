== Key findings

* *Keycloak already has SPIFFE client authentication.* A `spiffe` identity provider plus the `federated-jwt` client authenticator, preview since 26.4 and still preview in 26.8.2. RHBK 26.4.18 has the code, but the feature is off and the Keycloak is a shared RHDP instance.
* *On 26.4 the client id probably has to equal the SPIFFE ID.* From 26.5 a separate "Federated subject" field removes that need.
* *OpenShell `token_exchange` shipped in v0.0.113.* The final token has `sub` = the user and `azp` = the sandbox SPIFFE ID. The lab runs chart 0.0.92, which has no token grants.
* *The SPIRE Broker API for shared supervisors is not released yet* (OpenShell PR #4732, merged after v0.1.9).
* *The MCP Gateway needs one extra CEL predicate*, because Authorino authentication rules are OR, not AND. Both facts (user and agent) have to live in one token.

== Open questions

. ZTWIM sets `iss` to the OIDC discovery URL. Keycloak requires `iss` to match the identity provider, or to be missing when `sub` is a `spiffe://` URI. Test it.
. Keycloak wants one unique SPIFFE ID per client, but OpenShell sandbox IDs end in a UUID per sandbox. How do you register clients for sandboxes that come and go?
